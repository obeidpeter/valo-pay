# Import and shared-form usability slice

Inspected local baseline: `cc9cca4127d963d9f8a3a600091d502c08eb4239`; branch `codex/evidence-led-usability`. Work is local, synthetic and not deployed by this subtask. The parent task owns browser screenshots, full validation, release preparation and final audit integration.

## Evidence and contract

Repository evidence inspected in full: `artifacts/api-server/src/lib/valopay-import.ts`, `artifacts/valo-pay/src/components/import-wizard.tsx`, `record-dialog.tsx`, `review-dialog.tsx`, `form-field.tsx`, existing safe-mutation and protected-edit mechanisms. Also inspected server edit-version messages, create-record duplicate-reference handling, import API schema, permissions usage and relevant test fixtures.

The actual import contract is synthetic-only; one to 500 CSV records; up to 1.5 MB; quoted CSV fields supported; first ten rows previewed. A check commits nothing. A commit validates every row and changes state only when all new rows are valid. Duplicates are skipped rather than treated as invalid. A duplicate is identified by a non-empty reference within a record kind, and also source for payment observations. Amounts are converted to integer kobo by the existing shared validator. None of these backend rules was changed.

The form layer already preserved drafts in React state, guarded unsaved navigation and sent the original record revision. It did not store sensitive drafts in browser storage. These controls remain. The root task supplied the strengthened safe-mutation hook; this slice integrates its exact-original-request recovery with the three owned forms.

Evidence classification: source inspection and deterministic UI regression tests, using the real domain through the offline fake API. The lost-response import test wraps that API with a small response replay cache to emulate the server idempotency response contract; it is not a PostgreSQL concurrency test. No participants, external providers or physical devices were used here. Human performance and satisfaction remain unmeasured.

## Implemented interaction changes

Before: choose/paste → check → all row results at bottom → contradictory duplicate-only ready instruction; field correction can require scanning the whole form; a transport failure looks like a definite failure.

After: choose/paste with atomic-import and reference guidance → check → focus a named check result → review converted amounts and uniquely mapped columns → filter to rows needing correction or inspect all rows → commit → authoritative import result. Duplicate-only checks finish with an explicit no-change outcome. No frontend optimistic financial success was introduced.

For errors, click a summary correction to move to the correct retained field. Changing that field removes only its stale error. An explicit stale-revision error keeps the existing intentional discard-and-refresh remedy. A role/duplicate-reference refusal does not masquerade as a stale revision.

For a lost write response, the form states that the request may already have finished, locks changed submissions and offers **Retry same import/request/review**. The same original payload/key is replayed. An uncertain dialog can be deliberately closed only after an explicit warning that closing does not cancel the request and discards local retry information. Normal navigation still uses the existing unsaved-work guard. No fake undo, sensitive localStorage draft or automatic retry was added.

## Integrated-review follow-up, 22 September 2026

**UX-I08, severity 2:** A consequential payment comparison opens with its reason field automatically focused. On a short viewport this can scroll past the evidence the user is supposed to review. This is an expert finding about error prevention and recognition, affecting learnability, efficiency and errors; no participant frequency is claimed. Dialogs that contain contextual evidence now start with the title focused. Plain create forms still start at the first input. An invalid submit moves to the first invalid field as before. The added regression asserts the review title, reason-error focus, no accidental action request, and opener restoration. The browser spec separately checks the real title is in view, evidence headings, overflow and trapped tab order.

The focused post-change run of `usability-imports.test.tsx`, `reconciliation-workflow.test.tsx` and `forms.test.tsx` passed **3 files / 22 tests** (`work/usability-dialog-tests.log`). After integrated type checking identified an invalid Testing Library query option, that test-only option was removed. The final focused session/recovery run passed **2 files / 15 tests** (`work/usability-session-tests.log`): ten usability tests and five session tests. All four original late-response cases retain their existing assertions; the harness now models a forced external parent close while keeping the real dialog mounted, since intentional Cancel/close/Escape are blocked while a request is pending. The fifth session case explicitly proves those pending controls stay blocked, then the authoritative response closes the dialog and creates only one record.

Independent real-Chrome queue harness `work/check-queue-position.mjs` reproduced a root-owned navigation problem: a tall queue at 1,800px, then a short page, then return restored **0px** before the fix. After root changed the queue hook to capture scroll events before shorter content clamps the element, the same harness restored **1,800px**. It tests the actual React hook and Chrome layout; it is an engineering regression, not a human task-time measure.

Added `artifacts/valo-pay/e2e/usability.spec.ts` for root's integrated browser run. It covers tall-queue Back restoration, current role/mode/time-zone context, form correction and opener focus, payment comparison focus/overflow, and scoped Axe WCAG-tag checks on reconciliation, exceptions, settings and collections in both themes at tablet width plus 320 CSS-pixel reflow. These browser tests were **authored here; their integrated execution/result must be reported by root**. The limited route/state scan does not establish complete WCAG conformance, assistive-technology support, or human usability outcomes.

**UX-I09, severity 2:** Root's first integrated mobile Chromium run found the collections owner filter beyond the main column after resizing to 320 CSS pixels. The control was an intrinsic-width native select beside an unwrappable owner label. An isolated local Chrome reproduction using the captured real public font assets and generated CSS confirmed clipping even when it narrowly fits the wider main region: select right edge **306.83px**, enclosing clipping card right edge **304px**. This impairs the visible control and error-free filtering at narrow widths (efficiency, errors, satisfaction; WCAG 1.4.10). The label now stacks above a width-constrained select on phones; the inline desktop arrangement remains. The same reproduction using the actual new source classes puts the right edge at **287px**, inside the card. No server or shared app build was needed for that reproduction. The browser test now waits for final font metrics and strengthens its checks to require this select to fit its clipping card as well as the main viewport. The final integrated rerun is root-owned.

**UX-I10, severity 2:** In integrated review, root identified that retaining an uncertain write correctly across a later authentication/role refusal could conceal the refusal's recovery guidance. Both record and review dialogs now show the formatted **Latest response** within the persistent unknown-outcome warning. This conveys the latest obstacle without claiming that the original write failed, releasing the original retry key, or enabling changed submissions. Two new regressions each commit to the fake server, lose the response, receive structured HTTP 403 on replay, assert visible guidance and frozen data, then recover the original result. All three attempts carry identical keys/payloads, exactly one record exists, and a partial review preserves its submitted tasks. The focused `usability-imports.test.tsx` plus `record-dialog-session.test.tsx` run passed **2 files / 17 tests** (`work/usability-replay-tests.log`). This contributes to error recovery, learnability and efficiency; no human recovery-time improvement is inferred.
